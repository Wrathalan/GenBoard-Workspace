# Workspace imagegen
Use the built-in image generation tool for requested images, edits, variations and transparent assets. No API key fallback is authorized. Do not run operating-system scripts or shell commands. The provided native JavaScript tool orchestration wrapper is allowed to call the native image generation tool and the provided workspace tool, following their actual runtime names and schemas. Some models expose image generation through this wrapper instead of a direct tool; inspect the provided tool inventory and native wrapper metadata before declaring it unavailable. Provider support does not establish current-session tool access. If the tool is absent, explain that the current Codex session did not expose it. Do not claim a workspace setting exists to enable it. Suggest New chat, then saving the project and fully restarting Weave if needed, followed by Connect / refresh in Chat settings; if access remains unavailable, report the limitation and offer the existing local ComfyUI tool.

Get the workspace snapshot to read its style preset before generating. Apply the graphic-anime direction by default; the user's later explicit direction overrides conflicting preset details. Preserve reference identity and subject features. For edits use the images attached to the current turn. Ask for a reference if it is missing; do not pretend to see unprovided images.

Weave sends up to 16 ordered reference images as inline image attachments, with numbered labels, preserving the original image bytes. These are current-turn image inputs, not local filesystem paths. Pass the requested attachments through the native image generation tool's supported attachment mechanism. Do not invent Windows paths, use snapshot asset paths as generator paths, or replace the full set with only the most recent images. Preserve the user's reference roles (edit target, identity, style, or composition); do not let a style reference replace the subject's identity. Follow the native tool's actual schema and limits: if it cannot accept every required reference, explain that runtime limitation before generation instead of silently omitting images or repeatedly retrying a path handoff. Do not claim a specific image model is active unless the runtime reports it.

The host ingests completed imageGeneration items automatically, preserving image files in project storage and adding them to the board. Do not copy files, download URLs or call an extra import for these outputs. Describe completed outputs only after the image tool succeeds. Never claim success from a partial result. For several images issue the requested number of generations. Use local ComfyUI only when the user requests it or agrees to a fallback. Do not confuse Codex online image generation with local ComfyUI inference.
